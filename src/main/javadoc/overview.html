Ghostwriter API

Ghostwriter is an advanced documentation engine that automatically scans, analyzes, and assembles project documentation using embedded guidance tags and AI-powered synthesis. It supports all types of project files, including source code, documentation, project site content, and other relevant files.

The API is organized as a processing pipeline. Processors identify project files and workflow context, resolve configuration and prompts, and invoke generative-AI providers. Format-specific reviewers extract embedded guidance from supported file types. Functional AI tools provide controlled access to project files, commands, web content, reusable acts, and project-scoped workflow state.

Architecture

The diagram summarizes the principal types and their relationships: processor classes orchestrate guidance and act workflows, reviewers supply file-format-specific guidance extraction, and tool providers expose the controlled operations used by those workflows.

Packages

org.machanism.machai.gw.processor
Provides the project-aware processing pipeline. It processes files, folders, modules, and path-pattern matches; resolves configuration and prompt settings; discovers and applies inline guidance; and runs reusable TOML-defined Acts and ordered episode workflows. Processors can select providers and tools through prompt metadata, include prompt content from project-relative or web locations, and report the results of guidance-driven processing.
org.machanism.machai.gw.reviewer
Provides format-specific reviewers that locate @guidance instructions in Java, HTML/XML, Markdown, PlantUML, Python, TypeScript, and dedicated guidance text files and turn them into prompt fragments. Reviewers apply each format's comment conventions, preserve relative project-file context, and return no fragment when relevant guidance is absent.
org.machanism.machai.gw.tools
Provides Functional AI Tools and workflow infrastructure for controlled file, command, web, act, guidance, and project-context operations, including command safety checks, patch application, bounded command-log access, and workflow navigation controls. Tool groups expose annotated operations and reusable prompt templates to AI-driven workflows while keeping project paths and execution context controlled.

Typical use

Use the processor package to run a guidance-driven documentation update or a named Act against a project layout. The processor selects reviewers for candidate files, passes the resulting instructions to the configured AI provider, and registers the appropriate tool providers for the workflow. The tools package supplies the project-scoped operations that the provider can invoke while the reviewers package keeps guidance extraction consistent with each file format.
